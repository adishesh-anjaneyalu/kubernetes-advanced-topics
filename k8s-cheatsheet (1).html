Kubernetes Manifest

Cheat Sheet

Every manifest explained · Production ready · Written by reading code

🏠
Namespace
Separate rooms inside your cluster
v1
What it is: Like separate folders for different teams/environments. production, staging, monitoring all live in the same cluster but are isolated from each other.
namespace.yaml
apiVersion: v1
kind: Namespace
metadata:
  name: production     # name of your namespace
  labels:
    env: production
💡 Every other resource must have namespace: production in metadata
⚠️ Never deploy to default namespace in production
⚙️
ConfigMap
Non-sensitive config as env vars
v1
What it is: A store for non-sensitive config values like URLs, ports, feature flags. Injected into pods as environment variables. Never put passwords here!
configmap.yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: myapp-config
  namespace: production
data:                        # key: value pairs
  APP_ENV: "production"
  PORT: "8000"              # always strings!
  REDIS_HOST: "redis-service"
  DB_NAME: "hospitaldb"
  # ❌ NEVER put passwords here
✅ ConfigMap = APP_ENV, PORT, HOST names, feature flags
❌ Never = passwords, tokens, API keys, DATABASE_URL with password
💡 All values must be strings — use quotes around numbers
🔐
Secret
Sensitive data — passwords, tokens, keys
v1
What it is: Like ConfigMap but for sensitive data. Values must be base64 encoded under data:, OR use stringData: and Kubernetes encodes for you automatically.
secret.yaml
apiVersion: v1
kind: Secret
metadata:
  name: myapp-secret
  namespace: production
type: Opaque

# Option 1 — base64 encoded (manual)
data:
  DB_PASSWORD: cGFzc3dvcmQxMjM=   # base64!
  JWT_SECRET: c2VjcmV0a2V5

# Option 2 — stringData (auto-encodes) ✅ easier
stringData:
  DB_PASSWORD: "password123"   # plain text OK here
  JWT_SECRET: "secretkey"
🔑 Encode: echo -n "mypassword" | base64
✅ Use stringData: in dev — simpler, no encoding needed
🏭 In production use External Secrets Operator + AWS Secrets Manager
🚀
Deployment
Run your app, keep it alive, restart if crashed
apps/v1
What it is: The main manifest for stateless apps (APIs, frontends). Manages pod replicas, rolling updates, and restarts. Always read the Dockerfile to get port, image, and health path.
deployment.yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: myapp
  namespace: production
  labels:
    app: myapp
spec:
  replicas: 3
  selector:
    matchLabels:
      app: myapp        # 🔑 must match template labels
  template:
    metadata:
      labels:
        app: myapp      # 🔑 Service finds pods by this
    spec:
      imagePullSecrets:        # for private registries
        - name: ecr-secret
      containers:
        - name: myapp
          image: myapp:1.0.0   # ← your built image!
          ports:
            - containerPort: 8000  # from EXPOSE in Dockerfile
          envFrom:
            - configMapRef:
                name: myapp-config
            - secretRef:
                name: myapp-secret
          resources:
            requests:
              cpu: "100m"
              memory: "128Mi"
            limits:
              cpu: "500m"
              memory: "512Mi"
          readinessProbe:         # "ready for traffic?"
            httpGet:              # httpGet is a BLOCK!
              path: /health       # from your app code
              port: 8000
            initialDelaySeconds: 10
            periodSeconds: 5
          livenessProbe:          # "still alive?"
            httpGet:
              path: /health
              port: 8000
            initialDelaySeconds: 15
            periodSeconds: 10
🔑 matchLabels must match template.labels exactly
🐳 image = your built app image, NEVER the runtime (python:3.11, node:18)
🏥 httpGet is a block — path and port go INSIDE it
🔍 Check code for /health endpoint → use that as probe path
🔌
Service
Stable address to reach your pods
v1
What it is: Pods die and restart with new IPs. Service gives a stable address that never changes. It finds pods using labels and load balances across them.
service.yaml
apiVersion: v1
kind: Service
metadata:
  name: myapp-service
  namespace: production
spec:
  selector:
    app: myapp          # 🔑 must match Deployment pod labels
  ports:
    - protocol: TCP
      port: 80           # port YOU call from outside
      targetPort: 8000   # port app runs on (containerPort)
  type: ClusterIP        # internal only
  # type: LoadBalancer   # creates AWS ELB (external)
  # type: NodePort       # exposes on node IP (dev only)
🔑 selector.app must match Deployment template.labels.app
🌐 port = what callers use · targetPort = what pod actually listens on
☁️ Use ClusterIP for internal · LoadBalancer for external AWS access
🚪
Ingress
Front door — routes traffic by domain/path
networking.k8s.io/v1
What it is: Routes external traffic to the right Service based on domain name or URL path. One Ingress can route to multiple services. Needs NGINX Ingress Controller installed.
ingress.yaml
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:              # no space before metadata!
  name: myapp-ingress
  namespace: production
  annotations:
    nginx.ingress.kubernetes.io/rewrite-target: /
spec:
  ingressClassName: nginx
  rules:
    - host: myapp.example.com
      http:              # ONE http block per host!
        paths:
          - path: /
            pathType: Prefix   # required!
            backend:
              service:
                name: myapp-service
                port:
                  number: 80
          - path: /orders    # multiple paths, one http block!
            pathType: Prefix
            backend:
              service:
                name: orders-service
                port:
                  number: 80
⚠️ No space before metadata: — common indentation bug!
🔑 pathType: Prefix is required — don't forget it
📦 Multiple paths → ONE http: block, multiple items under paths:
📈
HorizontalPodAutoscaler
Auto scale pods up/down based on CPU/memory
autoscaling/v2
What it is: Watches CPU/memory usage. When traffic spikes → adds more pods automatically. When quiet → removes pods to save cost. Needs resources.requests set in Deployment to work.
hpa.yaml
apiVersion: autoscaling/v2
kind: HorizontalPodAutoscaler
metadata:
  name: myapp-hpa
  namespace: production
spec:
  scaleTargetRef:
    apiVersion: apps/v1
    kind: Deployment
    name: myapp         # must match Deployment name!
  minReplicas: 2        # 🔑 OUTSIDE scaleTargetRef!
  maxReplicas: 10       # 🔑 OUTSIDE scaleTargetRef!
  metrics:
    - type: Resource
      resource:
        name: cpu
        target:
          type: Utilization
          averageUtilization: 70  # scale up at 70% CPU
🔑 minReplicas and maxReplicas are at SAME level as scaleTargetRef
🔗 scaleTargetRef.name must exactly match your Deployment name
⚙️ Deployment must have resources.requests.cpu set or HPA won't work
💾
PersistentVolumeClaim
Request for storage that survives pod restarts
v1
What it is: Pods lose all data when they restart. PVC is your request for permanent storage. Think of it as reserving a hard drive for your pod. EBS = one pod. EFS = many pods.
pvc.yaml + deployment-with-volume.yaml
# 1. Create the PVC
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: myapp-pvc
  namespace: production
spec:
  accessModes:
    - ReadWriteOnce      # EBS: 1 pod | ReadWriteMany: EFS
  resources:
    requests:
      storage: 10Gi
  storageClassName: gp2   # gp2=EBS | efs-sc=EFS
---
# 2. Mount it in Deployment (inside containers:)
          volumeMounts:
            - name: mydata       # 🔑 must match volumes name
              mountPath: /app/data # folder inside container
# 3. Declare it (inside spec: same level as containers:)
      volumes:
        - name: mydata           # 🔑 must match volumeMounts
          persistentVolumeClaim:
            claimName: myapp-pvc # must match PVC name!
🔗 3-way connection: PVC name → claimName → volumes.name → volumeMounts.name
💿 EBS (gp2) = ReadWriteOnce = replicas: 1 only
📁 EFS (efs-sc) = ReadWriteMany = multiple replicas share storage
🗄️
StatefulSet
For databases — stable names, stable storage
apps/v1
What it is: Like Deployment but for stateful apps (databases). Each pod gets a fixed name (postgres-0, postgres-1) and its own dedicated PVC that always follows it. Needs a Headless Service.
statefulset.yaml
apiVersion: apps/v1
kind: StatefulSet
metadata:
  name: postgres
  namespace: production
spec:
  serviceName: postgres-headless  # must match Headless Service!
  replicas: 1
  selector:
    matchLabels:
      app: postgres
  template:
    metadata:
      labels:
        app: postgres
    spec:
      containers:
        - name: postgres
          image: postgres:15
          ports:
            - containerPort: 5432
          volumeMounts:
            - name: pg-data
              mountPath: /var/lib/postgresql/data
  volumeClaimTemplates:    # KEY difference from Deployment!
    - metadata:
        name: pg-data         # must match volumeMounts name
      spec:
        accessModes: ["ReadWriteOnce"]
        storageClassName: gp2
        resources:
          requests:
            storage: 20Gi
---
# Headless Service (required!)
apiVersion: v1
kind: Service
metadata:
  name: postgres-headless
spec:
  clusterIP: None           # ← makes it headless!
  selector:
    app: postgres
🔑 volumeClaimTemplates auto-creates a PVC per pod (postgres-data-postgres-0)
📡 Always needs a Headless Service (clusterIP: None)
🏭 In production on AWS → use RDS instead of StatefulSet!

RBAC (Role + ServiceAccount + RoleBinding)
Who can do what, where
rbac.authorization.k8s.io/v1
What it is: Controls what each pod/user is allowed to do in the cluster. ServiceAccount = identity. Role = permissions. RoleBinding = connects them.
rbac.yaml
# 1. Identity for your pod
apiVersion: v1
kind: ServiceAccount
metadata:
  name: myapp-sa
  namespace: production
---
# 2. What is this identity allowed to do?
apiVersion: rbac.authorization.k8s.io/v1
kind: Role              # ClusterRole = all namespaces
metadata:
  name: myapp-role
  namespace: production
rules:
  - apiGroups: [""]       # "" = core group
    resources: ["pods", "services"]
    verbs: ["get", "list", "watch"]
  - apiGroups: ["apps"]
    resources: ["deployments"]
    verbs: ["get", "list", "update"]
---
# 3. Connect SA to Role
apiVersion: rbac.authorization.k8s.io/v1
kind: RoleBinding
metadata:
  name: myapp-binding
  namespace: production
subjects:
  - kind: ServiceAccount
    name: myapp-sa         # must match ServiceAccount!
    namespace: production
roleRef:
  kind: Role
  name: myapp-role         # must match Role!
  apiGroup: rbac.authorization.k8s.io
# 4. Assign to Deployment under spec.template.spec:
#    serviceAccountName: myapp-sa
🔗 SA name → RoleBinding subjects → Role name → RoleBinding roleRef
🌍 Role = one namespace · ClusterRole = all namespaces
🚫 Never use default ServiceAccount in production pods

How to Read Any Dockerfile → Write YAML
The detective method — extract everything before writing
CHEAT CODE

📄 Read Dockerfile For

EXPOSE 8080     → containerPort: 8080
                  → targetPort: 8080
FROM node:18    → image: myapp:1.0.0
                  (NOT node:18 — your app!)
CMD [...:5000]  → confirms port 5000

🐍 Read App Code For

@app.get("/health")  → probe path: /health
os.getenv("DB_PASS") → goes in Secret
os.getenv("PORT")    → goes in ConfigMap
open("/app/data")   → needs PVC!

🔑 .env File Sorting Rule

ConfigMap (not sensitive):
PORT, APP_ENV, HOST names
DB_NAME, LOG_LEVEL, URLs

Secret (sensitive):
PASSWORDS, TOKENS, API_KEYS
DATABASE_URL (has password!)
Dockerfile ──→ EXPOSE ──→ containerPort + targetPort app code ──→ /health ──→ readinessProbe + livenessProbe path .env file ──→ sensitive? ──→ YES → Secret | NO → ConfigMap replicas ──→ stateless? ──→ YES → Deployment | NO → StatefulSet storage ──→ shared pods? ──→ YES → EFS (RWX) | NO → EBS (RWO)

Top 8 Bugs That Will Break Your YAML
The same mistakes kill every beginner — memorize these
AVOID THESE

❌ Wrong image

image: python:3.11  # runtime!
image: myapp:1.0.0  # correct

❌ httpGet as string

httpGet: /health    # wrong!
httpGet:            # correct
  path: /health
  port: 8000

❌ Secret not encoded

data:
  PASS: "plain"   # wrong!
stringData:
  PASS: "plain"   # correct

❌ HPA indent bug

  scaleTargetRef:
    name: myapp
    minReplicas: 2  # wrong!
  minReplicas: 2  # correct

❌ Dots in names

name: node.js-app  # wrong!
name: nodejs-app   # correct
# only a-z 0-9 hyphens!

❌ Labels mismatch

matchLabels: app: myapp
template labels: app: MY-APP
# all must be identical!

❌ Missing pathType

- path: /          # wrong!
  backend: ...
- path: /
  pathType: Prefix  # correct!

❌ Password in ConfigMap

DATABASE_URL: psql://  # has password!
  → ConfigMap = WRONG!
DATABASE_URL: psql://
  → Secret = correct!
